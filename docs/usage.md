## 身份与登录

管理员使用安装时设置的用户名和密码登录，负责账号、密钥、系统设置和运维。初始模板用户名为 `admin@cpr.local`；已有管理员改密走「系统设置 → 安全与访问 → 管理员密码」，修改 YAML 初始密码不会重置现有密码

密钥持有者在登录页选择 API Key 身份，只能查看本密钥的用量、额度与客户端配置。浏览器会话到期需要重新登录；会话期限与客户端 `/v1/*` 请求鉴权相互独立

不要混用三类凭据：上游账号凭据由网关保管，客户端密钥用于模型请求，管理 API Key 用于管理员接口。详细边界见[鉴权与公共约定](api.md#1-鉴权与公共约定)

## 账号

在「账号」中选择 Provider，使用对应的授权或导入入口添加账号。添加后检查启用状态、凭据、额度和支持模型；健康检查成功不代表该账号已可调用

代理先在「代理管理」中保存，再绑定到账号。出口测试用于诊断连接，不能证明账号授权和模型调用一定成功。导入账号与出口不会迁移其他系统的下游密钥、余额或历史用量

停用账号会停止参与调度，但不等于停止维护可刷新的 OAuth 凭据。恢复停用账号只重新启用，保留原有错误与额度事实；强制恢复也不会验证上游已经恢复，后续请求仍可能失败

账号导出可能包含敏感凭据，应按密钥保护，避免上传到公开问题、截图或聊天记录。Provider 能力与导入约束见[账号 API](api.md#5-账号)

## 账号分组

分组用于定义客户端密钥可使用的账号范围，可按使用者、用途或 Provider 组织，允许混合 Provider

- 密钥未绑定分组时，可使用全部账号
- 绑定多个分组时，范围为已启用分组成员的并集
- 分组授权不保证调度成功，账号仍须满足启用、凭据、额度、模型和并发条件

需要隔离使用者时，先建立明确的分组，再绑定密钥；不要用未绑定分组表示“暂时不给权限”。模型权限可在账号与密钥层进一步限制，合同见[分组](api.md#6-账号分组)和 [Client Key](api.md#7-client-key)

## 客户端密钥

创建密钥时设置名称、可用分组、模型限制，以及需要的并发、有效期和预算。将完整密钥交给对应使用者，通过「使用密钥」复制客户端配置或导入 CCSwitch

客户端持有密钥即可按其授权调用，避免多人共享同一密钥，否则用量无法按使用者区分。需要撤销访问时停用或删除该密钥，不必修改上游账号凭据

Key 预算与用量统计采用不同口径：预算账本可累计重试中已取得的费用，用量 Token 与费用聚合主要统计完整交付客户端的成功响应。费用未知也不等于实际免费，详情见[额度与预算](api.md#7-client-key)

## 验证客户端

先查询 `/v1/models` 验证地址和密钥，再用客户端发起一次真实 Responses 请求，核对管理端是否出现记录。模型目录成功不能替代真实推理验证；真实请求会消耗上游额度

Codex 配置优先使用管理端生成的内容，按操作系统合并后重启客户端。远程地址使用 HTTPS，Base URL 以 `/v1` 结尾。生图与 WebSocket 配置见[客户端配置](../deploy/README.md#客户端配置)，接口集成见[数据面合同](api.md#3-openai-数据面与模型目录)

## 运行设置

运行设置保存在所选数据库中，管理端保存后发布给新请求，重启不会用 YAML 覆盖。启动参数、存储连接、部署时区和日志仍归[部署配置](../deploy/README.md#配置归属)

| 设置 | 使用边界 |
| --- | --- |
| 上游客户端身份 | 可按 Provider 和 Key 覆盖，自动或固定版本不等于修改本地客户端版本 |
| 请求位置 | 默认关闭；代理位置优先于全局位置，不改变真实出口 IP 或部署时区，也不替代 `openai.residency` 数据驻留约束 |
| 调度、并发与排队 | 按账号容量和客户端需求调整，排队不能增加上游额度 |
| 模型映射与定价 | 映射控制请求模型，价格用于费用计算，不能保证上游实际账单一致 |
| 客户端最低版本 | 根据实际客户端版本设置，避免未经验证就阻止现有用户接入 |
| 预热与恢复探测 | 可能发起真实上游请求并消耗额度，启用前确认模型和时间 |

使用 API 保存设置时须先读取完整设置与 `configRevision`，按更新合同提交。收到 `409` 后重新读取并核对差异，不能直接覆盖他人的修改，见[运行设置 API](api.md#8-运行设置)

主题和界面偏好只保存在当前浏览器，不属于全局运行设置；主题实现与扩展见[管理端主题](theme.md)

## 隐私规则

隐私策略默认关闭，只处理经网关发送的 OpenAI 请求，不控制客户端直接发出的遥测。按要处理的承载位置选择范围，再配置匹配字段和动作，不要把策略开启视为所有内容已经脱敏

建议先用合成样本预览：核对处理后的正文、请求头和 metadata，以及每条规则的命中与状态，再启用。`unmatched` 表示未命中；`skipped` 表示执行失败后跳过，不能视为脱敏成功

`skip_rule` 会撤销本条规则修改并继续发送，`reject_request` 会阻止请求。涉及认证、会话、工具字段的删除或改写可能破坏调用；环境文本的替换应保留结构。规则范围、限制与预览格式见[隐私策略](api.md#隐私策略)

## 用量与诊断

### 日期范围

今日、近 7 天、近 30 天按部署 `host.timezone` 的自然日计算，近 7 天包含当天和前 6 天。自定义日期范围包含结束日期当天；浏览器时区不覆盖部署时区

同一轮查询的列表与图表共享时间锚点，翻页不移动范围，刷新才更新。账号的最近 24 小时柱状图使用小时窗口，与今日汇总不是同一时间范围，接口规则见[页面时间合同](api.md#页面时间合同)

### 统计与分摊

请求数与结果分布覆盖筛选范围内全部请求，Token、缓存、延迟与成本聚合仅统计已完整交付客户端的成功推理响应。连接预热不进入正常推理用量；未知指标应保持未知，不能按零理解

账号与密钥交叉诊断以 `accountKey` 维度查看，仅统计关联的 OpenAI OAuth 账号。API 的 `tokenShare` 按同一账号在所选范围内成功交付的 Token 计算份额

页面「账号分摊」支持账号和密钥两种视角，占比分母随选中的实体重新合计。该占比用于解释用量来源，不是上游账单或 Key 预算的费用分摊，详见[统计与诊断](api.md#10-dashboard用量与错误)

### 请求失败

1. 先核对密钥是否启用、过期或超预算，绑定分组与模型是否允许请求
2. 检查账号的凭据、额度、冷却、并发和代理状态
3. 在用量或错误列表打开请求详情，结合请求 ID、阶段与恢复关联定位失败；只凭入口 ID 可能需要查入口日志
4. 若无记录，检查鉴权、解析、路由或准入等入口拒绝，以及观测是否延迟；没有记录不能证明没有请求

首字延迟、上游响应耗时和总延迟采用不同计时边界，不能直接相加。诊断详情是脱敏且有界的观测，不是完整请求转储。系统健康、日志与 DNS 排障见[请求错误排查](../deploy/README.md#请求错误排查)
