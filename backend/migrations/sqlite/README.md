# SQLite 迁移

SQLite 使用独立于 PostgreSQL 的迁移集，以单文件空库作为初始化目标。迁移编号只在本目录内递增；PostgreSQL 的迁移历史不会被复制或修改。

已冻结迁移按字节不可变。后续 schema 变更必须新增编号 SQL，并将其 SHA-256 追加到 `.frozen-sha256`。CI 会检查已登记迁移未变、目录中的 SQL 均已登记，以及冻结清单相对 base 只追加。

```bash
cd backend/migrations/sqlite
sha256sum --check --strict .frozen-sha256
```

## 初始化与升级

可写启动自动创建空数据库并执行本目录迁移，HTTP 在初始化完成后才监听；升级前安排维护窗口并备份现有数据，不能同时运行另一个网关进程。只读插件帮助只打开已有数据库，不创建数据库或执行迁移

数据库迁移记录与 SQL 内容必须匹配，校验失败时停止启动。不要通过修改已应用 SQL、删除迁移记录或重建部署数据库绕过错误，应核对运行版本与迁移文件来源，再决定恢复或使用正确制品

SQLite 与 PostgreSQL 是独立数据集，修改 `store.backend` 不会转换业务数据。可写启动会收紧 Unix 数据库与 WAL/SHM 文件权限，服务和 CLI 使用同一运行用户

## 备份与恢复

运行中的备份通过 SQLite 快照生成一致副本，不能仅复制主库文件。恢复须先停止网关，核对完整性与 WAL/SHM，并离线处理快照中的备份任务、调度游标和到期清理条件；仅关闭计划不能阻止旧任务被执行或旧备份被清理

完整维护步骤见[SQLite 文件恢复](../../../deploy/README.md#sqlite-文件恢复)，本目录只维护 schema 与冻结规则
